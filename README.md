# Spir Shop — متجر كوزمتك ومنتجات عناية

متجر إلكتروني مفتوح المصدر بالكامل وتحت سيطرتك، مبني على **MedusaJS v2** (الخلفية + لوحة التحكم) و **Next.js** (متجر الويب / PWA / تطبيق تلكرام المصغّر).
مهيأ للسوق العراقي: الدينار العراقي، الدفع عند الاستلام، التوصيل حسب المحافظة، وواجهة عربية RTL.

```
apps/
├── backend/      Medusa: API + لوحة التحكم (/app) + بوت تلكرام + كتالوج ميتا
├── storefront/   Next.js: متجر الويب (PWA) + Telegram Mini App
└── mobile/       Expo: تطبيق أندرويد وآيفون مع نظام تحديثات (انظر apps/mobile/README.md)
```

## ما الموجود حالياً

| الميزة | المكان |
|---|---|
| منطقة العراق، عملة IQD، الدفع عند الاستلام، توصيل بغداد (5,000) والمحافظات (7,000)، أقسام الكوزمتك ومنتجات تجريبية | `apps/backend/src/migration-scripts/initial-data-seed.ts` |
| إشعار تلكرام بكل طلب جديد (الاسم، الهاتف، العنوان، المنتجات، المجموع) | `apps/backend/src/subscribers/order-placed-telegram.ts` |
| بوت تلكرام: رسالة ترحيب + زر يفتح المتجر داخل تلكرام | `apps/backend/src/api/telegram/webhook/route.ts` |
| كتالوج فيسبوك/إنستغرام (XML) يتحدّث تلقائياً | `GET /feeds/meta` ← `apps/backend/src/api/feeds/meta/route.ts` |
| واجهة عربية RTL، أسعار بصيغة `25,000 د.ع`، حقل المحافظة كقائمة، الهاتف إجباري | `apps/storefront/src` |
| PWA (إضافة للشاشة الرئيسية) | `apps/storefront/src/app/manifest.ts` |
| دعم Telegram Mini App | `apps/storefront/src/lib/telegram/telegram-mini-app.tsx` |

## التشغيل محلياً

المتطلبات: Node 22.23+، PostgreSQL 15+، Redis.

```bash
npm install

# 1) الخلفية
cd apps/backend
cp .env.template .env            # عدّل DATABASE_URL وباقي القيم
npx medusa db:migrate            # ينشئ الجداول + بيانات العراق والمنتجات التجريبية
npx medusa user -e you@example.com -p 'كلمة-سر-قوية'
npm run dev                      # http://localhost:9000/app  ← لوحة التحكم

# 2) المتجر (في نافذة ثانية)
cd apps/storefront
cp .env.template .env.local
# ضع NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY من لوحة التحكم: Settings → Publishable API Keys
# NEXT_PUBLIC_DEFAULT_REGION=iq
npm run dev                      # http://localhost:8000
```

## منصة التطبيق (مثل Tapcart و Shopney)

كل هذا تديره من لوحة التحكم (`/app`) بدون تحديث التطبيق على المتاجر:

| الصفحة في اللوحة | الوظيفة |
|---|---|
| **مصمم التطبيق** | سحب وإفلات أقسام الصفحة الرئيسية، ومعاينة حية على شكل هاتف، و«نشر» يظهر فوراً عند كل الزبائن. فيه سجل للنسخ مع استرجاع أي نسخة سابقة. |
| **قصص التطبيق** | قصص بالصور أو الفيديو مثل إنستغرام، مع زر يفتح منتجاً أو قسماً، وترتيب وتاريخ انتهاء. |
| **إشعارات التطبيق** | إرسال إشعار لكل الزبائن أو لمحافظة معيّنة، مع سجل الإرسال. تذكير السلة المتروكة يُرسل **تلقائياً**. |
| **صفحة المنتج ← ألوان الدرجات** | لون لكل درجة (أحمر شفاه، فاونديشن...) يظهر كدائرة ملونة في التطبيق والموقع. |

### كيف تعمل الواجهة الديناميكية (Server-Driven UI)
- الصفحة الرئيسية بالتطبيق قائمة من «بلوكات» يقرأها من `GET /store/app-layouts/home`.
- البلوكات المتوفرة: `hero_banner` (بانر)، `story_bar` (القصص)، `countdown_offer` (عرض بعدّاد، يختفي تلقائياً عند الانتهاء)، `video_banner` (فيديو)، `product_carousel` (سلايدر منتجات)، `product_grid` (شبكة منتجات)، `category_chips` (الأقسام)، `heading` (عنوان)، `spacer` (مسافة).
- الروابط بصيغة `/product/<handle>`، `/category/<id>` أو `/category/all`، `/cart`، أو رابط خارجي `https://...`.
- التطبيق يحفظ آخر تصميم فيفتح حتى بدون إنترنت. وإذا وصل بلوك ما يعرفه إصدار قديم يتخطاه، وإذا فشل بلوك واحد ما يتأثر باقي الصفحة.
- **إضافة بلوك جديد:** تبني المكوّن في `apps/mobile/src/sdui/blocks/`، وتسجله في `apps/mobile/src/sdui/Renderer.tsx`، وتضيفه لإعدادات المصمم في `apps/backend/src/admin/lib/builder-config.tsx`. بعدها ارفع نسخة جديدة من التطبيق (أو تحديث OTA إذا ما يحتاج مكتبة Native).

### المعاينة الحية في المصمم
المصمم يعرض نسخة الويب من التطبيق داخل إطار هاتف ويرسل له المسودة أثناء التعديل. شغّلها بـ `cd apps/mobile && npx expo start --web` (المنفذ 8081)، وغيّر الرابط من أعلى صفحة المصمم إذا كانت على عنوان آخر. أضف هذا العنوان لـ `STORE_CORS`.

### الإشعارات
- التطبيق يسجّل جهاز الزبون تلقائياً (`POST /store/push-tokens`) مع رقم السلة والمحافظة.
- الإرسال يتم عبر خدمة Expo Push. يحتاج `eas init` حتى يصير للتطبيق `projectId`. على آيفون يحتاج مفتاح APNs، و `eas credentials` يجهّزه.
- الأجهزة اللي حذفت التطبيق تتعطل تلقائياً.
- تذكير السلة المتروكة: مهمة كل 30 دقيقة، ترسل مرة واحدة لكل سلة بعد `ABANDONED_CART_HOURS` ساعة (الافتراضي 3). النص قابل للتغيير بـ `ABANDONED_CART_TITLE` و `ABANDONED_CART_BODY`.
- تجربة التذكير فوراً: `ABANDONED_CART_HOURS=0 npx medusa exec ./src/scripts/dev/run-abandoned-cart-job.ts`

## ربط بوت تلكرام

1. افتح [@BotFather](https://t.me/BotFather) ← `/newbot` واحفظ التوكن.
2. لمعرفة `TELEGRAM_ADMIN_CHAT_ID`: أرسل رسالة للبوت (أو أضفه لمجموعة الموظفين)، ثم افتح
   `https://api.telegram.org/bot<TOKEN>/getUpdates` وخذ قيمة `chat.id`.
3. في `apps/backend/.env`:
   ```
   TELEGRAM_BOT_TOKEN=...
   TELEGRAM_ADMIN_CHAT_ID=...
   TELEGRAM_WEBHOOK_SECRET=أي-نص-عشوائي-طويل
   BACKEND_PUBLIC_URL=https://api.yourdomain.com
   STOREFRONT_URL=https://yourdomain.com
   ```
4. بعد النشر على HTTPS شغّل مرة وحدة:
   ```bash
   cd apps/backend && npx medusa exec ./src/scripts/telegram-setup.ts
   ```
   يسجّل الـ webhook ويضيف زر «المتجر» في قائمة البوت ليفتح المتجر كتطبيق مصغّر.

تجربة شكل رسالة الطلب بدون بوت حقيقي:
`npx medusa exec ./src/scripts/dev/test-telegram-notification.ts`

## ربط فيسبوك وإنستغرام (Meta Catalog)

1. أنشئ حساب [Meta Business](https://business.facebook.com) واربط صفحة الفيسبوك وحساب إنستغرام التجاري.
2. Commerce Manager ← Catalog ← Data sources ← **Data feed** ← Scheduled feed.
3. الرابط: `https://api.yourdomain.com/feeds/meta` — التحديث كل ساعة.

> ⚠️ ميزة وسم المنتجات في المنشورات ومتجر إنستغرام قد لا تكون مفعّلة للحسابات في العراق. حتى بدونها، الكتالوج يُستخدم لإعلانات الكتالوج الديناميكية (Advantage+ Catalog Ads).
> كل منتج يحتاج صورة حتى يقبله ميتا — أضف الصور من لوحة التحكم.

## النشر

| الجزء | المنصة | ملاحظات |
|---|---|---|
| الخلفية + لوحة التحكم | **Railway** (خدمة `backend` من `Dockerfile.backend`) | مع Postgres و Redis على نفس المشروع، و volume على `.medusa/server/static` للملفات المرفوعة |
| تطبيق الويب (PWA) | **Railway** (`Dockerfile.web`) أو **Vercel** (`apps/mobile`) | نفس كود تطبيق الموبايل، انظر القسم الجاي |
| متجر Next.js (اختياري) | **Vercel** (المجلد `apps/storefront`) | الإعدادات في `apps/storefront/vercel.json` |
| تطبيق الموبايل | GitHub Actions ← Releases | انظر `.github/workflows/android-apk.yml` |

### الخلفية على Railway
- **Pre-deploy command:** `sh /app/apps/backend/deploy/release.sh`، وهو يشغّل الـ migrations وينشئ أول مدير (ومعه البيانات التجريبية إذا كان `SEED_DEMO=true`). يشتغل مرة وحدة قبل كل نشر، وإذا فشل يبقى الإصدار القديم شغّال.
- **المتغيرات:** `RUN_RELEASE_ON_START=false` (لأن الـ pre-deploy يتكفّل بالمهمة)، و `DATABASE_URL=${{Postgres.DATABASE_URL}}`، و `REDIS_URL=${{Redis.REDIS_URL}}`، و `JWT_SECRET` و `COOKIE_SECRET` بقيم عشوائية طويلة، و `ADMIN_EMAIL` و `ADMIN_PASSWORD`.
- **فحص الصحة:** `/health`.
- `STORE_CORS` و `AUTH_CORS` لازم تحتوي دومين متجر Vercel.
- على أي استضافة Docker ثانية: `start.sh` يشغّل `release.sh` تلقائياً قبل تشغيل السيرفر.

### تطبيقان على أندرويد: للزبائن وللإدارة
من نفس الكود ينبني تطبيقان مستقلان، وكل واحد يتنصب لوحده على الهاتف:

| التطبيق | الملف | الوظيفة |
|---|---|---|
| **Spir Shop** (`com.spirshop.app`) | `spir-shop-X.Y.Z.apk` | تطبيق الزبائن: تصفح، سلة، طلب، تتبع |
| **Spir Shop - الإدارة** (`com.spirshop.app.admin`) | `spir-shop-admin-X.Y.Z.apk` | تطبيق صاحب المتجر (الشاشات بالأسفل) |

شاشات تطبيق الإدارة:
- **الرئيسية:** طلبات اليوم ومبيعاته، عدد الطلبات بكل حالة، اختصارات، وآخر الطلبات.
- **الطلبات:** بحث بالاسم أو الهاتف أو الرقم، وفلتر حسب الحالة. صفحة الطلب فيها زر اتصال وزر واتساب، والمنتجات والمجموع، ومراحل الطلب. الطلب يمشي بهالترتيب: «تأكيد» ← «تسليم للمندوب» ← «تم التسليم»، أو «إلغاء». الزبون يوصله إشعار بكل مرحلة.
- **المنتجات:** إضافة وتعديل منتج بالصور (من المعرض أو الكاميرا)، والاسم، والسعر بالدينار، والوصف، والقسم، وإظهاره أو إخفاؤه، والحذف. المنتجات اللي بيها عدة أحجام أو درجات تتعدل أسعارها من لوحة التحكم.
- **الإعلانات:** بانرات أعلى الصفحة الرئيسية والقصص. تختار صورة ونص وشنو يفتح عند الضغط، وتظهر للزبائن فوراً.
- **المزيد:** إرسال إشعار لكل الزبائن أو لمحافظة وحدة، واختيار المتجر، وتسجيل الخروج.

تفاصيل إضافية:
- الدخول بنفس بريد وكلمة مرور لوحة التحكم، والجلسة تنحفظ بالتخزين الآمن بالهاتف. صاحب أي متجر يشوف متجره فقط.
- **البناء:** GitHub Actions يبني الملفين بكل إصدار ويرفقهما بنفس الـ Release، وكل تطبيق يحدّث نفسه من ملفه. محلياً: `APP_VARIANT=admin ./scripts/build-apk.sh`.
- **تجربته بالمتصفح:** افتح نسخة الويب وأضف للرابط `?app=admin`، مثلاً `http://localhost:8081/admin?app=admin`.
- **ملاحظة:** النسخ من 1.1 لحد 1.4 كانت متجهة على `localhost`، فما توصل للسيرفر ولا تقدر تحدّث نفسها. لازم تنزّل نسخة 1.5.0 أو أحدث يدوياً من GitHub Releases.

### تطبيق واحد للويب وأندرويد و iOS
تطبيق Expo بالمجلد `apps/mobile` هو نفس الكود للثلاث منصات:

| المنصة | البناء | النشر |
|---|---|---|
| **الويب (PWA)** | `cd apps/mobile && npm run build:web`، والناتج بالمجلد `dist/` | Railway: خدمة جديدة من `Dockerfile.web`. أو Vercel: Root Directory هو `apps/mobile`، والإعدادات جاهزة بـ `vercel.json` |
| **أندرويد** | GitHub Actions ← Android APK | ينزل كـ GitHub Release، والتطبيق يحدّث نفسه |
| **iOS** (لاحقاً) | `npm run build:ios` (EAS Build) | يحتاج حساب Apple Developer، وبعدها `eas submit -p ios` |

- نسخة الويب تنضاف للشاشة الرئيسية مثل التطبيق (أيقونة، شاشة كاملة، RTL)، وتفتح حتى بدون إنترنت بآخر نسخة محفوظة.
- على شاشات الكمبيوتر تظهر بعمود بعرض الهاتف بوسط الصفحة.
- إشعارات الهاتف وتحديث ملف APK تشتغل بأندرويد و iOS فقط. بالويب كل تحديث ينزل تلقائياً مع كل نشر جديد.
- **مهم:** أضف دومين نسخة الويب لمتغيرات الخلفية `STORE_CORS` و `AUTH_CORS`، لأن المتصفح يتصل بالخلفية مباشرة.
- **متغيرات البناء:** `EXPO_PUBLIC_MEDUSA_BACKEND_URL` (رابط الخلفية)، و `APP_STORE` (أي متجر، والافتراضي `spir`).
- متجر Next.js بالمجلد `apps/storefront` صار اختيارياً: نفعه بس إذا تحتاج صفحات تفهرسها Google (SEO) أو تطبيق تلكرام المصغّر.

### متجر الويب على Vercel
- Root Directory: `apps/storefront`.
- المتغيرات: `NEXT_PUBLIC_MEDUSA_BACKEND_URL` (رابط Railway)، و `NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY` (من `GET <backend>/mobile/config`، أو من لوحة التحكم ← Settings ← Publishable API Keys)، و `NEXT_PUBLIC_DEFAULT_REGION=iq`، و `NEXT_PUBLIC_BASE_URL` (دومين المتجر).

### صلاحيات المتاجر
- مدير المنصة (`PLATFORM_ADMIN_EMAILS`، وإذا ما موجود فـ `ADMIN_EMAIL`) يدير كل المتاجر.
- أي مستخدم ثاني باللوحة يشوف ويعدّل فقط المتاجر اللي بريد مالكها («owner_email») هو بريده: المصمم، القصص، الإشعارات، الإعدادات، التقييمات، وتأكيد الطلب.
- صفحات Medusa الأساسية (المنتجات، الطلبات، الزبائن) بعدها مشتركة. لعزل كامل يحتاج كل صاحب متجر لوحة منفصلة.

### للإنتاج
- الصور تنحفظ على volume في Railway. إذا كبر المتجر أو صار يشتغل على أكثر من نسخة، انقلها لـ Cloudflare R2 أو S3 (`@medusajs/file-s3`).
